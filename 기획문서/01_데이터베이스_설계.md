# 데이터베이스 설계 (Supabase / PostgreSQL)

SQL 원본: `supabase/` 폴더. 변경은 **사용자가 Supabase SQL Editor에 붙여넣어 실행**한다(서비스 키를 쓰지 않음).
SQL Editor: https://supabase.com/dashboard/project/ghrjtbznjnvzwqthiahm/sql/new

## 함수 (security definer)
- `is_member(crew)` / `shares_crew(other)`: RLS 재귀 방지용 판단 함수
- `create_crew(name)`, `join_crew(code)`: 크루 생성·가입 (crew_members 직접 insert 정책 없음)
- `handle_new_user()` 트리거: 가입 시 profiles 생성(닉네임 = 가입 시 입력값 → 이름 → 메일 앞부분)
- `pokes_guard()` 트리거: 쿨다운 검사 + 오래된 약올리기 삭제

## 보안 규칙 요약 (RLS)
- 기본: 로그인한 사용자만(authenticated). anon 접근 없음
- 프로필·장비: 나 + 같은 크루만 보기, 본인만 수정
- 운동 기록: 내 것 + 같은 크루의 visibility='crew'만 보기, 본인만 쓰기·수정·삭제
- 반응·댓글: 볼 수 있는 기록에만, 본인 것만 쓰기. 댓글은 기록 주인도 삭제 가능
- 약올리기·챌린지: 같은 크루 안에서만
- private_notes, body_profile, body_logs: 본인만 (크루원·운영자 화면에서도 안 보임)
- 사진 버킷 `photos`(비공개, 5MB, jpeg/png/webp): 경로 `<user_id>/<uuid>.jpg`, 같은 크루만 서명 URL로 열람, 본인만 업로드·삭제

## 알려진 한계 / 다음 변경 후보 (004~)
- hide_stats: 심박·칼로리는 004에서 서버 처리. **페이스는 시간·거리로 계산되므로 화면에서만 숨김**(완전히 숨기려면 거리나 시간을 숨겨야 함). 숨긴 칼로리는 크루 칼로리 랭킹에 0으로 들어감
- 랭킹·챌린지 합산을 폰에서 함 → 서버 함수(RPC)로 이전 (DB 시간대는 004에서 Asia/Seoul)
- 탈퇴(006): 앱이 저장소 API로 `<내 id>/` 사진을 먼저 지우고 `delete_me()` 호출. SQL로 storage.objects 를 직접 지우면 실제 파일이 남으므로 이 순서 유지. 사진 삭제 후 함수가 실패하면 계정만 남음(다시 탈퇴하면 됨)
- crews.created_by 가 cascade 라 만든 사람이 지워지면 크루가 통째로 사라짐 → delete_me 가 먼저 넘김. 대시보드에서 사용자를 직접 지울 때는 주의
- 신고는 feedback(005). 차단은 007. 새 건의·신고 알림(메일 등)도 없음 → 대시보드에서 직접 확인
- 건강정보 동의는 008(앱에서 강제: 내 몸 탭·심박 칸). 서버 정책으로 신체 기록 쓰기를 막지는 않음 → 필요하면 body_* 정책에 동의 확인 추가
- challenges.metric 에 points 추가하려면 check 제약 변경
