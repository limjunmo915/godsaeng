# 09. 갓생살기 워치 앱 기획 (2026-11-07)

삼성 헬스를 거치지 않고 **갤럭시워치(Wear OS)에 우리 앱을 직접 깔아** 종목별 동작(스윙·점프·펀치·반복)을 세는 기능.
아직 기획 단계. 개발 시작 전 결정할 것은 맨 아래 '결정할 것'.

---

## 1. 벤치마킹: 비슷한 앱
| 앱 | 기기 | 하는 일 | 배울 점 | 아쉬운 점 |
|---|---|---|---|---|
| Swingli | 애플워치 | 포핸드·백핸드·서브 자동 구분, 손목에서 실시간 스윙 수, 계정 없이 무료 | 운동 중 손목 화면에 **숫자 하나 크게**, 가입 없이 바로 | 애플워치만 |
| Terava | 애플워치 | 포·백핸드, 탑스핀·슬라이스, 서브·스매시, **랠리 수** | 랠리 단위 기록 → 경기 흐름 | 애플워치만 |
| Zepp Tennis | 애플워치 + 전용 센서 | 포·백·발리·스매시·서브 분류, 센서 달면 공 속도·회전 | 워치만으로 기본, 장비 붙이면 고급 | 별도 센서 구매 |
| TennisKeeper | 애플워치 | 포·백·서브 횟수 + 스윙 속도, 폰에서 점수 기록 | **점수판 + 스윙 기록**을 한 화면에 | 애플워치만 |
| SwingVision | 아이폰 카메라 + 워치 | 영상 분석·라인 판정 | 영상 AI(먼 미래) | iOS 전용, 유료 |
| JumRop·YaoYao | 애플워치 | 줄넘기 횟수 자동 | 분당 점프, 연속 기록 | 애플워치만 |
| 어메이즈핏·화웨이 | 자사 워치 | **줄넘기 모드 기본 내장** | 줄넘기가 인기 종목이라는 신호 | 자사 기기만 |
| 가민 Strength | 가민 워치 | 근력 운동 **반복 횟수 자동** | 세트·휴식 자동 구분 | 머신 운동은 잘 못 셈 |
| 삼성 헬스 | 갤럭시워치 | 일부 근력 운동 반복 자동, 운동 자동 감지 | 기본 기능 수준 | 테니스 스윙·줄넘기 수 없음 |
| 스트라바·NRC | 워치 앱 | 거리·시간·심박·지도 | 종료 후 피드 공유 흐름 | 종목별 동작은 안 셈 |

**정리:** 테니스 스윙·줄넘기 횟수를 세는 앱은 **거의 애플워치 전용**이고, **갤럭시워치(Wear OS)용은 빈자리**예요. 갓생살기는 여기에 **크루 약올리기**(예: "민수 오늘 스윙 420번, 너는?")를 붙일 수 있어서 차별점이 생겨요.
정확도는 앱마다 과장이 많아요(근력 반복 약 70% 수준이라는 자료도 있음). 그래서 **"추정치"라고 표시**하고, 끝난 뒤 사용자가 고칠 수 있게 해요.

## 2. 어떻게 만드나 (구조)
```
갤럭시워치(Wear OS 앱, Kotlin)                       폰(지금 앱 + 안드로이드 플러그인)
├ 운동 시작·정지 화면(큰 숫자 1개 + 심박)            ├ 측정 화면 '⌚ 워치로 측정' 선택
├ Health Services: 심박·걸음·워치 GPS              ├ 종목 고르면 워치에 "시작" 신호
├ 동작 센서(가속도·자이로, 초당 50번)                ├ 실시간 숫자 받아 표시(스윙 수·심박)
│  └ 종목별 감지기(스윙·점프·펀치·케이던스·반복)        ├ 종료 → 기록 화면에 자동 채움(+스윙 수)
├ 진동·안내("라켓 잡는 손에 차 주세요")               └ 올리면 피드 카드에 '스윙 420' 표시
└ 폰과 연결: Wearable Data Layer(블루투스, 폰 없으면 워치에 저장했다 나중에 보냄)
```
- 원시 센서 값(가속도 수만 개)은 **워치 안에서만 계산**하고, 폰·서버엔 **결과(횟수·최고 세기 등)만** 보냄 → 배터리·개인정보 둘 다 유리
- 워치 앱은 지금 안드로이드 앱과 **같은 이름·같은 Play 등록**(Wear OS 버전 추가)으로 올림
- 개발 장비: 갤럭시워치 6 실기기 필수(에뮬레이터론 센서 시험 불가), 워치 '개발자 모드' 켜고 무선 설치

## 3. 종목별 감지 방법(1차 설계)
| 종목 | 착용 안내 | 세는 것 | 감지 방법 | 1차 목표 정확도 |
|---|---|---|---|---|
| 테니스·배드민턴·스쿼시·탁구·피클볼 | 라켓 잡는 손 | 스윙 수, 가장 센 스윙, 랠리 수 | 손목 회전 속도(자이로)가 기준값을 넘는 순간 1번, 0.4초 안에 다시 안 셈. 2차: 회전 방향으로 포핸드·백핸드 | 스윙 90%+ |
| 골프 | 주로 쓰는 손 | 스윙 수(연습 포함) | 크게 들어 올렸다 빠르게 내리는 패턴 | 85%+ |
| 줄넘기 | 아무 손 | 점프 수, 분당 점프, 최장 연속 | 위아래 가속도가 일정 리듬으로 튀는 순간 | 95%+ |
| 복싱·킥복싱 | 한 손(양손이면 둘 다) | 펀치 수, 펀치 세기 | 앞쪽으로 짧고 강한 가속 | 85%+ |
| 달리기·걷기 | 아무 손 | 케이던스(분당 걸음), 걸음 수 | Health Services 걸음 수 사용 | 기기 수준 |
| 웨이트·홈트 | 운동하는 팔 | 반복 수, 세트, 휴식 | 같은 동작이 되풀이되는 주기 찾기 | 70~80%(2차) |
| 수영 | 아무 손 | 스트로크, 바퀴 | 2차 이후 | — |
- 감지 기준값은 **실제로 쳐 보며 조정**(설정에 '민감도' 3단계)
- 끝나면 "스윙 418번(추정)" + 사용자가 숫자 고치기 가능

## 4. 기능 트리(마인드맵)
```
갓생살기 워치
├─ 1. 연결
│   ├─ 폰 앱 측정 화면 → '⌚ 워치로 측정'
│   ├─ 워치에서 바로 시작(폰 없이도) → 나중에 자동 동기화
│   └─ 연결 상태 표시(끊기면 워치에 저장)
├─ 2. 종목별 측정
│   ├─ 라켓: 스윙 수 · 최고 스윙 · 랠리 · (2차) 포/백 구분
│   ├─ 골프: 스윙 수
│   ├─ 줄넘기: 점프 수 · 분당 점프 · 최장 연속
│   ├─ 복싱: 펀치 수 · 세기
│   ├─ 달리기·걷기: 케이던스 · 걸음 · 워치 GPS 거리
│   ├─ 웨이트(2차): 반복 · 세트 · 휴식
│   └─ 공통: 시간 · 심박(평균·최고) · 칼로리
├─ 3. 안내·피드백
│   ├─ 시작 전 착용 안내("라켓 잡는 손에")
│   ├─ 진동: 100번마다 · 목표 달성
│   ├─ 음성(폰) · 큰 숫자 1개 화면
│   └─ 목표: 스윙 500번 · 줄넘기 1,000개
├─ 4. 기록·공유
│   ├─ 종료 → 기록 화면 자동 채움(+종목별 숫자)
│   ├─ 피드 카드: '스윙 420 · 최고 세기 ★'
│   ├─ 크루 랭킹: 이번 주 스윙왕 · 줄넘기왕
│   └─ 약올리기: "민수 오늘 스윙 420번, 너는?"
├─ 5. 설정
│   ├─ 주로 쓰는 손(왼/오)
│   ├─ 감지 민감도(낮음·보통·높음)
│   └─ 진동·화면 꺼짐 동작
└─ 6. 안전·법
    ├─ 결과만 저장(원시 센서 값 저장 안 함)
    ├─ 심박 = 건강정보 동의자만
    ├─ "의료용 아님 · 추정치" 표시
    └─ Play 건강 앱 신고 · 워치 품질 기준
```

## 5. 단계 계획
| 단계 | 내용 | 끝나면 할 수 있는 것 |
|---|---|---|
| 0. 준비 | 워치 개발자 모드 켜기, 워치 앱 뼈대(Kotlin·Compose for Wear), GitHub 자동 빌드에 워치 앱 추가 | 워치에 빈 앱 설치 |
| 1. 연결 | 폰↔워치 신호(시작·정지·실시간 숫자), 측정 화면 '⌚ 워치로 측정' | 폰에서 시작 → 워치 심박이 폰에 뜸 |
| 2. 1차 종목 | **테니스(스윙) · 줄넘기(점프) · 달리기(케이던스)** 감지기, 착용 안내, 진동 | 실제로 쳐 보며 횟수 확인 |
| 3. 기록 | 기록·피드·랭킹에 종목별 숫자(DB `workouts.metrics` 칸 추가, SQL) | 피드에 '스윙 420' |
| 4. 확장 | 골프·복싱·배드민턴 등 라켓 종목, 워치 단독 시작·나중 동기화 | |
| 5. 2차 | 포/백핸드 구분, 웨이트 반복, 수영 | |
| 6. 출시 | Wear OS 품질 기준 점검, Play에 워치 버전 등록 | |

## 6. 법령·정책 검토 (변호사 검토 아님 — 출시 전 확인 권장)
| 항목 | 판단 | 할 일 |
|---|---|---|
| **의료기기 해당 여부** (의료기기법) | 식약처 판단기준상 **운동·레저 목적의 심박 측정은 '웰니스 제품'으로 의료기기 아님**. 질병 진단·치료·예방 목적이면 의료기기(2026-02 지침 개정에도 원칙 같음) | 화면·스토어에 **"의료 목적이 아니며 질병을 판단할 수 없어요"** 표시. '부정맥 감지', '건강 진단' 같은 표현 금지 |
| **개인정보·민감정보** (개인정보보호법) | 심박 = 건강정보 → **이미 있는 건강정보 별도 동의**로 처리. 스윙·점프 횟수는 운동 기록(일반 개인정보). 원시 동작 데이터는 워치에서 계산 후 버림 | 처리방침에 '워치 동작 센서로 횟수 계산(원시 데이터 저장 안 함)' 추가 |
| **위치정보** (위치정보법) | 워치 GPS 경로도 지금 경로 정책 그대로(동의자만, 200m 가림, 제공 기록) | 위치기반서비스사업 신고(출시 전, 이미 숙제) |
| **Play 건강 앱 신고** | **비공개 테스트 포함 모든 트랙**에서 필수. 심박은 '피트니스' 분류 | Play Console '건강 앱' 신고서 작성 |
| **Play 센서·하드웨어 고지** | 기기 센서·외부 기기(워치)가 필요하면 **스토어 설명에 지원 기기 명시** 필수. 심박 등 신체 센서 권한은 안드로이드 16부터 세분화 | 설명에 "갤럭시워치4 이후 Wear OS 워치 필요" 명시, 권한은 필요한 것만 |
| **Wear OS 품질 기준** | 기준 미달이면 심사 거절. 2026-09-15부터 64비트 필수 | 출시 전 체크리스트 점검 |
| **표시·광고** (표시광고법) | "정확한 스윙 분석" 같은 과장 금지 | '추정치' 문구, 정확도 수치는 직접 시험한 것만 |
| **전파법·KC 인증** | 우리는 소프트웨어만 만들고 기기를 팔지 않아서 해당 없음 | — |
| **다른 앱 따라하기** | 기능 아이디어는 자유. 이름·로고·화면 그대로 베끼기는 금지 | Swingli·Zepp 등 이름·디자인 안 씀 |

## 7. 상표 등록 어디에, 어떻게
- **어디:** 특허청 전자출원 **특허로**(https://www.patent.go.kr)에서 직접 출원(또는 변리사 의뢰)
- **누구 이름으로:** 앱 운영자·Play 개발자와 같게 **아내분 명의** 추천(나중에 회사 만들면 회사로 이전 가능)
- **무엇을:** '갓생살기' 글자만으로는 식별력 부족 거절 위험(08 문서 상표 검색 결과) → **로고(갓 심박 아이콘·깐족이) + 글자**를 합친 상표 추천. 캐릭터 '깐족이'도 따로 출원 검토
- **어느 분류(류):** 9류(앱·소프트웨어), 41류(운동 지도·피트니스 정보 제공), 42류(앱 서비스 제공·SaaS), 45류(소셜 네트워킹)
- **비용(관납료, 특허로에서 최신 금액 확인):** 출원료 전자출원 1류당 약 6만 2천 원, 등록료 1류당 약 20만 1천 원(10년, 분할 납부 가능), 우선심사 1류당 약 16만 원. 4개 류면 출원 약 25만 원 + 등록 약 80만 원
- **기간:** 보통 1년 안팎, 우선심사면 몇 달
- **직접 출원 순서:** 특허로 회원가입 → 출원인 코드 받기 → 공동인증서 등록 → 상표출원서(지정상품은 특허청 고시 명칭에서 고르기) → 수수료 납부
- 식별력 판단이 애매해서 **출원 전 변리사 상담 1회** 추천

## 8. 결정할 것
1. 1차 종목: **테니스·줄넘기·달리기**로 시작할까요?
2. 워치에서 **폰 없이 단독 시작**도 1차에 넣을까요(나중 동기화)? → 안 넣으면 더 빨리 끝남
3. 상표 출원: 직접(특허로) vs 변리사, 그리고 출원 시점(비공개 테스트 중 vs 출시 직전)
